# Brainstorm: skill-optimize

> 深度探索记录 — 精简 ai-tools-bridge skill，减少 token 消耗

## 需求描述

对 ai-tools-bridge 中的 14 个 SKILL.md 进行精简，在原有功能不变（行为逻辑不变 + 所有细节不变）的情况下减少 token 消耗。

**背景**：
- ai-tools-bridge 是 Claude Code 插件，实现 SDD 工作流编排器
- 14 个 SKILL.md 共 2716 行，10 个 reviewer/reference 文件 680 行，总计 3396 行
- 最大文件：sdd-brainstorm（472 行）、sdd-plan（285 行）、sdd-quick（212 行）
- 发现大量重复内容：触发条件、输出约束、零结果防护、角色加载、拆分模式、review 循环

**目标**：
- 减少 token 消耗（AI 加载 SKILL.md 时的上下文占用）
- 保持所有功能完整性
- 提高可维护性（公共逻辑改一处即可）

## 方案探索

### 方案 A: 共享模块 + 引用（推荐）

将重复内容提取到 `skills/_shared/` 目录，SKILL.md 通过 `<!-- include: path -->` 引用。

**共享模块**：
| 文件 | 内容 | 预估行数 | 被引用次数 | 原始占用 | ROI |
|------|------|----------|------------|----------|-----|
| `base-triggers.md` | 通用触发条件模板 | 30 | 14 | ~420 行（14×30） | 高 |
| `output-constraints.md` | 输出约束 + 零结果防护 | 25 | 14 | ~350 行（14×25） | 高 |
| `role-loading.md` | 角色加载完整逻辑 | 120 | 9 | ~1080 行（9×120） | 高 |
| `breakdown-mode.md` | 拆分模式检测 + 交互流程 | 100 | 1 | ~100 行（仅 sdd-brainstorm） | 中 |
| `review-loop.md` | review 循环模式 | 60 | 2 | ~120 行（sdd-brainstorm + sdd-plan） | 中 |

**ROI 说明**：
- breakdown-mode 仅 sdd-brainstorm 使用（472 行中约 120 行），提取后净节省约 20 行，但提高可维护性
- review-loop 在 sdd-brainstorm 和 sdd-plan 中重复（共约 160 行），提取后净节省约 100 行
- 如果 ROI 不明显，可考虑将 breakdown-mode 合并到 sdd-brainstorm 内联，review-loop 保留提取

**优点**：
- 重复内容只写一次，维护方便
- 各 SKILL 职责清晰，只关注差异
- 预估减少 40-50% SKILL.md 行数，32% 总行数

**缺点**：
- 需要约定 include 机制（HTML 注释 + AI 解析）
- 完整理解需查看多个文件

### 方案 B: 内联压缩 + 脚注引用

保持单一文件结构，将重复内容压缩为简短标记，详细定义放在共享文件。

**优点**：
- 不改变文件结构，向后兼容
- 实现简单

**缺点**：
- 压缩程度有限（约 20-30%）
- 仍需查看共享文件理解完整逻辑

### 方案 C: 分层架构 + YAML 元数据

引入 `SKILL.yaml` 元数据文件声明配置，SKILL.md 只保留纯逻辑。

**优点**：
- 结构化元数据，易于工具处理
- SKILL.md 大幅精简

**缺点**：
- 需要修改加载机制支持 YAML
- 改动较大

### 方案比较

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 精简效果 | 40-50% | 20-30% | 50-60% |
| 改动规模 | 中等 | 小 | 大 |
| 维护性 | 优秀 | 一般 | 优秀 |
| 向后兼容 | 需约定 | 完全兼容 | 需修改加载 |

**选择方案 A**：在精简效果和改动规模之间取得最佳平衡，且维护性优秀。

## 边界条件与异常处理

### 共享模块覆盖机制

当某个 SKILL.md 的触发条件或行为有特殊变体时：

1. **差异覆盖**：在 `<!-- include -->` 之后直接写差异内容，共享模块提供默认值，SKILL 可覆盖
2. **示例**：
   ```markdown
   <!-- include: ../_shared/base-triggers.md -->
   **触发**：用户执行 `/sdd-brainstorm`，或说"探索需求"...
   **不触发**：需求已明确（→ `/sdd-propose`）
   ```
   共享模块定义通用格式，各 SKILL 填充具体触发词

### Include 解析失败降级

如果 `<!-- include: path -->` 解析失败（文件不存在、路径错误）：

1. **降级策略**：SKILL.md 仍可独立运行，共享模块内容缺失时使用 SKILL 内的内联内容
2. **验证方式**：在 Phase 3 验证中检查所有 include 路径有效性
3. **错误提示**：AI 遇到无效 include 时输出警告但不阻断执行

### 不适合提取的内容

以下内容保留在各 SKILL.md 中，不提取到共享模块：
- 各 SKILL 特有的前置依赖检查（如 sdd-brainstorm 无前置依赖）
- 核心执行逻辑（委托目标、Override 指令）
- 后置逻辑的差异部分（产物校验内容、完成引导格式）

## 关键决策

### 决策 1: 采用共享模块 + 引用机制
- **选择:** 创建 `skills/_shared/` 目录，SKILL.md 通过 `<!-- include: path -->` 引用
- **理由:** 最符合"混合方式"需求，公共模块提取 + 各 SKILL 内部可进一步压缩
- **被否决的替代:**
  - 方案 B（内联压缩）：精简效果有限（仅 20-30%）
  - 方案 C（YAML 元数据）：改动规模大，需要修改加载机制

### 决策 2: 保持所有细节不变
- **选择:** 行为逻辑不变 + 所有细节不变，精简只优化表达方式和结构
- **理由:** 用户明确要求功能完整性，不能删减任何功能
- **被否决的替代:**
  - 删除边缘情况描述：会导致功能丢失
  - 压缩示例和错误处理：会影响可理解性
- **功能完整性验证标准**:
  - [ ] 触发条件：触发词、不触发条件、歧义处理 100% 保留
  - [ ] 前置逻辑：校验流程、角色加载、拆分模式逻辑 100% 保留
  - [ ] 核心执行：委托目标、Override 指令 100% 保留
  - [ ] 后置逻辑：review 循环、产物校验、完成引导 100% 保留
  - [ ] 输出格式：模板、示例、错误提示 100% 保留
  - [ ] 配置项：默认值、可选值、验证逻辑 100% 保留

### 决策 3: 双轨验证方式
- **选择:** 结构验证（vitest 测试）+ 内容验证（diff 审查）+ 语义验证（逐条对比）
- **理由:** 三者结合确保功能完整性
- **被否决的替代:**
  - 仅测试：无法验证内容完整性
  - 仅 diff：无法验证结构正确性
- **语义验证步骤**:
  1. 提取原始 SKILL.md 中的每条指令（触发词、校验规则、输出格式等）
  2. 在新版本中逐条查找对应指令
  3. 生成覆盖率报告（指令保留率必须 = 100%）

### 决策 4: 5 个共享模块划分
- **选择:** base-triggers、output-constraints、role-loading、breakdown-mode、review-loop
- **理由:** 覆盖所有重复内容，职责单一
- **被否决的替代:**
  - 更细粒度（10+ 模块）：增加复杂度
  - 更粗粒度（2-3 模块）：职责不够清晰

## 约束识别

### 技术约束
- SKILL.md 的 frontmatter 格式必须保持不变（Claude Code 插件加载依赖）
- include 机制需兼容现有的文件读取方式
- 共享模块路径必须相对路径，便于子模块管理

### 性能约束
- **Include 解析方式**：纯约定（AI 自行解析），不修改 Claude Code 插件代码
- **加载延迟**：每次加载 SKILL.md 需额外读取 1-5 个共享文件，预估增加 10-50ms
- **缓存策略**：共享模块内容在会话内缓存，不重复读取
- **验证方式**：通过实际加载测试确认延迟在可接受范围

### Include 兼容性验证
- **Claude Code 插件加载机制**：插件读取 SKILL.md 全文作为 prompt，不解析 HTML 注释
- **`<!-- include: path -->` 语法**：纯约定标记，AI 在解析 SKILL.md 时识别并加载对应文件
- **兼容性**：HTML 注释在 Markdown 中不可见，不影响原有行为
- **验证步骤**：
  1. 确认 Claude Code 插件不会因 include 标记报错
  2. 确认 AI 能正确识别和解析 include 指令
  3. 确认共享模块路径解析正确（相对路径基准为 SKILL.md 所在目录）

### 团队约束
- 改造过程需保持可追溯性（每步可验证）
- 验证通过后才能提交
