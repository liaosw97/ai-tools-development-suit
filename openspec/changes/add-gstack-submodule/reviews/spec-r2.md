## Issues

### MEDIUM

#### Issue-6: proposal 优先级表述存在歧义

**位置:** `proposal.md` 决策追溯

**问题:** proposal.md 第 36 行声明：
```
选择 [内置 < 项目级 < 用户级] 而非 [单一配置源]：项目级配置可覆盖用户级，团队协作时项目配置优先生效
```

此处存在逻辑矛盾：
- "内置 < 项目级 < 用户级" 表示用户级优先级最高
- "项目级配置可覆盖用户级" 表示项目级优先级更高

**分析:**
- brainstorm.md 决策 4 原文："选择 [内置 < 项目级 < 用户级]：项目级配置可覆盖用户级，内置角色作为基础。这样团队协作时项目配置优先生效。"
- spec SC-05 已修正为："内置 < 项目级 < 用户级" 且 "项目级配置优先生效（团队协作时）"

**根本原因:** brainstorm 原文本身存在表述矛盾，spec 已按"内置 < 项目级 < 用户级"修正，但 proposal 和 brainstorm 的解释文字仍保留矛盾表述。

**建议:** 统一表述为以下之一：
1. 若用户级优先级最高：删除"项目级配置可覆盖用户级"，改为"用户级配置可覆盖项目级和内置"
2. 若项目级优先级最高：将优先级改为"内置 < 用户级 < 项目级"

根据 gstack 设计理念（团队协作时项目配置应优先生效），建议采用方案 2，并同步修正 spec SC-05。
