# Proposal: evaluate-refactor-accuracy

> 变更提案 — 评估 ai-tools-bridge 重构后的准确度损失

## 变更意图

评估 ai-tools-bridge 功能重构后与原本未重构的功能相比，准确度是否有损失，产出可量化的评估结论。

## 范围

### 包含
- 静态 Diff 分析：对比重构前后的 SKILL.md 文件，识别丢失/变更的逻辑
- 精度测试验证：运行 `tests/precision/` 和 `tests/unit/` 测试套件，验证算法准确度
- 场景走查：使用"简单变更"和"复杂变更"两个场景进行端到端验证
- 评估报告：产出变更清单、精度报告、评估结论

### 不包含
- 修复已识别的问题（仅评估，不修复）
- 性能基准测试（仅评估准确度，不评估性能）
- 重构代码（保持现有代码不变）

## 决策追溯

- 选择 [组合方案（A + B + C）] 而非 [单独使用方案 A/B/C]：兼顾效率和全面性，静态分析快速定位，精度测试量化指标，场景走查验证端到端（见 brainstorm.md §决策 1: 评估方法选择）
- 选择 [覆盖所有重构内容] 而非 [仅评估 Token Optimization]：用户明确要求全面评估，不应遗漏任何重构维度（见 brainstorm.md §决策 2: 评估范围界定）
- 选择 [简单+复杂两个场景] 而非 [仅使用简单变更场景]：简单场景验证核心流程，复杂场景验证边界情况和跨模块协调（见 brainstorm.md §决策 3: 场景选择）
- 选择 [定义量化指标] 而非 [无量化标准]：需要明确的标准来评估重构是否引入准确度损失（见 brainstorm.md §决策 4: 通过/失败标准）

## 影响分析

### 影响的模块
- `skills/sdd-*` — 所有 SDD skill 文件（SKILL.md 和子模块）
- `lib/` — Token Optimization 模块（summarizer、artifact-bridge、review-context、state-file）
- `roles/` — 角色系统定义文件
- `tests/` — 测试套件（精度测试和单元测试）

### 风险评估
- 低风险：评估操作为只读，不修改现有代码
- 中风险：场景走查可能需要实际执行环境，但可使用现有 fixture 替代

## 成功标准

- [ ] 信息保留率 ≥ 95%（摘要保留的关键信息比例）
- [ ] 所有精度测试通过（`tests/precision/` 和 `tests/unit/`）
- [ ] 场景走查无阻塞问题（简单+复杂场景均能正常走通）
- [ ] 语义完整性：无功能丢失（通过静态 diff 确认）
- [ ] 产出评估报告：变更清单、精度报告、评估结论
