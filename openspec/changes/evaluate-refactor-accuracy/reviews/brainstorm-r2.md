## Issues

### [minor] 组合方案执行顺序的依赖关系未明确
- **位置:** brainstorm.md §方案比较
- **描述:** 方案比较指出"先用方案 A 快速识别明显问题，再用方案 B 验证算法准确度，最后用方案 C 做端到端验证"，但未说明各方案之间的依赖关系。如果方案 A 发现重大问题（如关键逻辑丢失），是否应暂停并修复后再执行方案 B/C？还是继续完成全部评估后再统一处理？
- **建议:** 补充执行策略说明，例如："方案 A 发现 critical 级问题时，暂停评估并记录阻塞项；major 级问题记录后继续执行方案 B/C。"

### [minor] "信息保留率 ≥ 95%"阈值依据不足
- **位置:** brainstorm.md §决策 4
- **描述:** 通过标准定义"信息保留率 ≥ 95%"，但未说明该阈值的来源或合理性。为什么是 95% 而非 90% 或 99%？该指标如何测量（人工评估还是自动化）？
- **建议:** 补充阈值设定依据，例如："参考 summarizer 模块的设计目标（`guidelines/token-optimization.md`），或说明该阈值为初始基准值，后续可根据实际测试结果调整。"

### [minor] 组合方案场景数量选择理由可更明确
- **位置:** brainstorm.md §方案比较 / §决策 3
- **描述:** 方案 C 提出"2-3 个典型场景"，组合方案和决策 3 选择"简单+复杂"2 个场景。虽然数量在方案 C 的范围内，但未明确说明为何不选择 3 个场景（加入中等变更）。
