# Design: evaluate-refactor-accuracy

> 技术设计 — 评估 ai-tools-bridge 重构后的准确度损失

## 技术方案

### 整体架构

采用组合评估方案，分三个阶段执行：

1. **阶段 1: 静态 Diff 分析** — 快速识别明显问题
2. **阶段 2: 精度测试验证** — 量化算法准确度
3. **阶段 3: 场景走查** — 验证端到端完整性

### 阶段 1: 静态 Diff 分析

**目标**：识别重构前后的功能差异

**执行步骤**：
1. 使用 `git diff 4c20a61..ebd11c9 -- skills/` 获取所有 skill 变更
2. 按模块分组分析：
   - 核心流程（SKILL.md 主文件）
   - 子模块（modules/ 目录）
   - 角色系统（roles/ 目录）
3. 使用检查清单验证：
   - 关键函数/逻辑是否保留
   - 配置项是否完整
   - 错误处理是否一致
   - 输出格式是否变更

**产出**：变更清单（丢失/变更的逻辑）

### 阶段 2: 精度测试验证

**目标**：量化摘要算法的准确度

**执行步骤**：
1. 前置验证：检查现有测试覆盖范围
2. 运行测试：`pnpm test` 执行全部测试
3. 分析结果：检查通过率和覆盖率指标

**关键指标**：
- 信息保留率 ≥ 95%
- 所有精度测试通过

**产出**：精度报告（通过率、覆盖率指标）

### 阶段 3: 场景走查

**目标**：验证端到端流程完整性

**执行步骤**：
1. 选择场景：
   - 简单变更：`tests/fixtures/precision/simple-change/`
   - 复杂变更：`tests/fixtures/precision/complex-change/`
2. 模拟 SDD 流程：sdd-brainstorm → sdd-propose → sdd-plan
3. 验证点：
   - brainstorm 输出是否保留完整需求信息
   - proposal 是否正确引用 brainstorm 决策
   - plan 是否正确链接 spec 场景

**产出**：场景走查结果（通过/阻塞问题）

## 决策追溯

- 选择 [简单+复杂两个场景] 而非 [仅简单场景]：覆盖核心流程和边界情况（见 proposal.md §决策追溯）

## 依赖关系

- git commit 4c20a61 — 重构前的代码版本
- vitest — 测试运行环境
- `tests/fixtures/precision/` — 场景数据

## 风险缓解

- 风险：测试覆盖不全
- 缓解：在评估报告中注明未覆盖的内容

- 风险：场景走查需要实际执行环境
- 缓解：使用现有 fixture 替代
