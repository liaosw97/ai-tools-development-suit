## Issues

### [minor] 静态 Diff 分析 THEN 的"无功能丢失"断言难以自动化验证
- **位置:** specs/accuracy-evaluation/spec.md §静态 Diff 分析 THEN 第 4 条
- **描述:** "无功能丢失：所有重构前的关键函数/逻辑在重构后均有对应实现"是一个语义级断言，需要人工判断逻辑等价性，无法完全自动化验证。这与 brainstorm 方案 A 的已知缺点一致（"需要人工判断语义等价性"），但 spec 层面应明确标注验证方式。
- **建议:** 在该断言后补充验证方式说明，例如"（需人工审查 diff 输出，确认语义等价）"，或将其从 THEN 移至边界条件作为注意事项。

### [minor] 场景走查 WHEN 的验证点仍偏格式化
- **位置:** specs/accuracy-evaluation/spec.md §场景走查 - 简单变更 WHEN、§场景走查 - 复杂变更 WHEN
- **描述:** WHEN 中的验证点（"包含 §需求描述、§方案探索、§关键决策"、"引用 brainstorm 决策编号"、"包含 spec 链接"）仍为格式级检查。虽然 THEN 已增加语义断言，但 WHEN 的验证点描述了"检查什么"，如果 WHEN 只列出格式检查，执行者可能忽略语义层面的验证。
- **建议:** 在 WHEN 验证点中增加一条语义检查提示，例如"检查 brainstorm 决策是否被 proposal 正确采纳"，与 THEN 的语义断言呼应。
