## Issues

### [severity: minor] 边界条件未融入场景的 GIVEN/THEN
- **位置:** specs/accuracy-evaluation/spec.md §边界条件
- **描述:** Round 1 建议将边界条件融入对应场景的 GIVEN/THEN 中。修订后边界条件增加了"关联场景"标注，但仍以独立段落存在。读者需要跨段落关联才能理解完整场景，且边界条件未出现在对应场景的 GIVEN 前置条件或 THEN 断言中。
- **建议:** 将边界条件拆分融入对应场景：边界情况 1（测试覆盖不全）作为"精度测试验证"的 GIVEN 前置条件（"测试覆盖范围可能不完整"）或失败路径；边界情况 2（执行环境）作为场景走查的 GIVEN（"可使用现有 fixture 替代实际执行环境"）；边界情况 3（calculateCoverage）作为"精度测试验证"的 WHEN 步骤。

### [severity: minor] 静态 Diff 分析的"无功能丢失"验证方式不够具体
- **位置:** specs/accuracy-evaluation/spec.md §静态 Diff 分析 THEN
- **描述:** THEN 第三条"无功能丢失：所有重构前的关键函数/逻辑在重构后均有对应实现"仍是语义性描述。虽然比 Round 1 有改进（增加了"关键函数/逻辑在重构后均有对应实现"的说明），但判定"对应实现"的方法未明确——是逐函数名匹配、逐文件覆盖检查、还是人工审查？
- **建议:** 补充判定方法，例如："无功能丢失：通过变更清单逐项检查，每个 REMOVED/MODIFIED 的关键函数/逻辑在变更清单中均有对应的 ADDED 项或保留确认标记"。

### [severity: minor] 场景走查 THEN 的"输出产物格式正确"未列出具体字段
- **位置:** specs/accuracy-evaluation/spec.md §场景走查 - 简单变更 THEN、§场景走查 - 复杂变更 THEN
- **描述:** "输出产物格式正确：符合模板要求"作为可测试断言，未指明需要检查哪些模板字段。不同场景的产出物（brainstorm.md、proposal.md、plan.md）各有不同的模板结构。
- **建议:** 列出关键模板字段检查项，例如："brainstorm.md 包含 §需求描述、§方案探索、§关键决策 段落；proposal.md 包含 §变更意图、§范围、§决策追溯 段落；plan.md 的任务步骤包含 [spec:domain#scenario] 链接"。
