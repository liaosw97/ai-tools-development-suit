# Proposal: hierarchical-requirement-breakdown

> 变更提案 — 定义意图、范围和关键决策

## 变更意图

为 SDD 工作流增加**需求分层拆分**能力，实现渐进式探索和独立功能验证，支持复杂需求的模块化实施。

## 范围

### 包含

- **sdd-brainstorm 改动**
  - 新增拆分模式检测（参数 `--breakdown` / `-b` + 自然语言触发）
  - 新增交互式拆分流程（L1→L2→L3 即时追问）
  - 新增功能树产出格式（写入 brainstorm.md 的"功能拆分"节）
  - 新增目录冲突检测（拆分过程中发现相似目录时询问用户）

- **sdd-plan 改动**
  - 新增功能树读取逻辑（解析 brainstorm.md 中的功能树）
  - 新增依赖检测规则（数据依赖、API 依赖、UI 依赖）
  - 新增任务组标注格式（`[unit:模块/单元/功能点]`）
  - 新增 checkpoint 标记（功能单元间插入检查点）

- **sdd-code 改动**
  - 新增功能单元选择逻辑（列出功能单元状态，用户选择实现目标）
  - 新增目录冲突检测（创建文件前扫描相似目录并询问）
  - 新增功能单元独立验证（仅验证相关测试）
  - 更新完成引导（推荐下一功能单元）

- **配置扩展**
  - openspec/config.yaml 新增 `breakdown` 节

### 不包含

- 新增制品类型（如 `breakdown.md`）
- 改变现有制品依赖链
- 强制所有需求走拆分流程（仅可选增强模式）
- 嵌套目录结构（保持扁平目录 + spec 内嵌套）

## 决策追溯

- 选择 [方案 A 轻量增强] 而非 [方案 B 独立制品]：改动范围小，不增加制品复杂度，用户无需学习新制品（见 brainstorm.md §方案比较）
- 选择 [三个阶段都修改] 而非 [仅修改 brainstorm]：拆分能力贯穿需求探索、计划生成、代码实施全流程（见 brainstorm.md §决策 1）
- 选择 [即时触发追问] 而非 [拆完所有层后统一追问]：确保在追问结果基础上继续拆分下一层，信息连贯（见 brainstorm.md §决策 2）
- 选择 [默认独立 + 异常提示] 而非 [自动分析依赖排序]：避免误判依赖关系，由用户确认依赖关系（见 brainstorm.md §决策 3）
- 选择 [brainstorm 和 code 阶段都检测] 而非 [仅在 code 阶段检测]：brainstorm 阶段可能错误引用已有模块（见 brainstorm.md §决策 4）
- 选择 [用户可干预拆分深度] 而非 [固定三层]：适应不同复杂度的需求（见 brainstorm.md §决策 5）
- 选择 [可选增强模式] 而非 [默认行为]：对简单需求不增加不必要开销（见 brainstorm.md §决策 6）
- 选择 [参数和自然语言都支持] 而非 [仅参数触发]：提高可发现性（见 brainstorm.md §决策 7）
- 选择 [扁平目录 + spec 内嵌套] 而非 [嵌套目录结构]：保持目录结构简洁（见 brainstorm.md §决策 8）
- 选择 [按功能单元顺序实现] 而非 [并行实现]：确保独立验证，降低协调复杂度（见 brainstorm.md §决策 9）

## 影响分析

### 影响的模块

- `ai-tools-bridge/skills/sdd-brainstorm/SKILL.md` — 新增拆分模式检测、交互流程、功能树产出
- `ai-tools-bridge/skills/sdd-plan/SKILL.md` — 新增功能树读取、依赖检测、任务组标注
- `ai-tools-bridge/skills/sdd-code/SKILL.md` — 新增功能单元选择、目录冲突检测、独立验证
- `schemas/sdd/templates/brainstorm.md` — 新增"功能拆分"节格式（可选）
- `openspec/config.yaml` — 新增 `breakdown` 配置节（可选）

### 风险评估

- **低风险**：拆分模式为可选增强，不影响现有工作流
- **兼容性**：现有 SDD 流程完全兼容，不启用拆分模式时行为不变
- **学习曲线**：新概念较少，用户可通过自然语言触发

## 成功标准

- [ ] 执行 `/sdd-brainstorm --breakdown` 或说"拆分需求"可进入拆分模式
- [ ] 拆分模式下 AI 提议 L1/L2/L3 层级并即时追问细节
- [ ] brainstorm.md 包含结构化的"功能拆分"节
- [ ] sdd-plan 能读取功能树并按功能单元生成任务组
- [ ] sdd-code 能列出功能单元状态并按用户选择实施
- [ ] 目录冲突时 AI 暂停并询问用户确认目标目录
- [ ] 不启用拆分模式时 SDD 行为与之前一致
