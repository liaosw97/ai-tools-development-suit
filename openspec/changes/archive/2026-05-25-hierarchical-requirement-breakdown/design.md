# Design: hierarchical-requirement-breakdown

> 技术设计 — 描述实现方案和技术决策

## 技术方案

### 方案概述

采用轻量增强方案，在现有 SDD skill 定义中嵌入拆分逻辑，不改变制品结构和依赖链。

实现方式：
1. **sdd-brainstorm** — 新增拆分模式检测和交互流程，产出功能树节
2. **sdd-plan** — 新增功能树解析和依赖检测，产出按功能单元分批的 plan.md
3. **sdd-code** — 新增功能单元选择和目录冲突检测，按单元独立验证

## 决策追溯

- 选择 [方案 A 轻量增强] 而非 [方案 B 独立制品]：改动范围小，不增加制品复杂度（见 brainstorm.md §方案比较）
- 选择 [方案 A 轻量增强] 而非 [方案 C 深度集成]：与"可选增强模式"设计目标一致（见 brainstorm.md §方案比较）

## 数据模型

### 新增/修改的数据结构

无新增数据结构。功能树信息存储在 brainstorm.md 的 Markdown 格式中。

### 功能树 Markdown 格式

```markdown
## 功能拆分

> 拆分模式启用时间：YYYY-MM-DD HH:MM

### 功能树

- **<模块名>** (L1)
  - **<单元名>** (L2)
    - <功能点> (L3) — 追问：<追问内容>
```

解析规则：
- L1：一级无序列表项，加粗 `**模块名**`
- L2：二级无序列表项，加粗 `**单元名**`
- L3：三级无序列表项，普通文本，可含追问标注

## 接口设计

### 新增接口

无新增 API 接口。所有交互通过 SDD skill 的 Markdown 提示词定义。

### 配置接口

**openspec/config.yaml 新增节**：

```yaml
breakdown:
  enabled: true           # 是否启用拆分模式（默认 true）
  default-depth: 3        # 默认拆分层数（默认 3）
  keywords:               # 自然语言触发关键词
    - 拆分
    - 分层
    - 逐步探索
    - 功能模块
  dependency-detection: true    # 是否启用依赖检测（默认 true）
  directory-conflict-detection: true  # 是否启用目录冲突检测（默认 true）
```

## 实现策略

### 批次划分

**批次 1：sdd-brainstorm 改动**
- 1.1 拆分模式检测逻辑
- 1.2 L1/L2/L3 交互流程
- 1.3 功能树产出格式
- 1.4 目录冲突检测（brainstorm 阶段）
- 1.5 异常流处理（取消、矛盾）

**批次 2：sdd-plan 改动**
- 2.1 功能树解析逻辑
- 2.2 依赖检测规则
- 2.3 任务组标注格式
- 2.4 用户确认依赖流程

**批次 3：sdd-code 改动**
- 3.1 功能单元选择逻辑
- 3.2 目录冲突检测（code 阶段）
- 3.3 功能单元独立验证
- 3.4 完成引导更新

**批次 4：配置与文档**
- 4.1 配置节定义
- 4.2 测试用例
- 4.3 文档更新
