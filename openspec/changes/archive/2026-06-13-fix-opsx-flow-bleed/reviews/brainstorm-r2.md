## Issues

### [minor] 验收标准指标表述不够精确

- **位置:** §验收标准（第 188 行）
- **描述:** 指标 1 "主流程无泄露：执行 `/sdd-propose` → `/sdd-ff` → `/sdd-code` 完整流程时，用户不会看到引导至 `/opsx:apply` 的建议"表述不够精确。实际上 OPSX 的输出仍然会显示，只是被 SDD 的后置逻辑覆盖。
- **建议:** 改为"SDD 后置逻辑优先：执行完整 SDD 流程时，SDD 的下一步建议必须在输出的最后位置显示，覆盖 OPSX 的建议"

### [minor] 功能拆分 L1/L2 边界模糊

- **位置:** §功能拆分（第 243-249 行）
- **描述:** L1（流程控制层）和 L2（输出格式层）实际上是同一件事的两个方面——SDD 后置逻辑增强既涉及流程控制也涉及输出格式。拆分为两层增加了认知负担但没有实际收益。
- **建议:** 合并为单一层次："SDD 后置逻辑增强（流程控制 + 输出格式）"

### [minor] 约束 2 假设未验证

- **位置:** §约束识别 > 约束 2（第 212-219 行）
- **描述:** "Claude Code 的 skill 执行模型中，invoke 的底层 skill 输出会先显示"是一个技术假设，但未提供验证方式或参考资料。
- **建议:** 添加验证方法，如"可通过测试 `/sdd-propose` 执行后的输出顺序验证此约束"

### [minor] 方案 C 实现模板不完整

- **位置:** §方案 C（第 65-80 行）和§推荐方案 > 短期方案（第 265-287 行）
- **描述:** 只展示了 `sdd-propose` 的后置逻辑模板，其他 12 个 action 的具体格式未说明。虽然列出了需要修改的文件，但没有通用模板。
- **建议:** 添加一个通用后置逻辑模板，说明哪些部分需要根据具体 action 定制
